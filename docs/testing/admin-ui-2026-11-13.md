## Lưu dữ liệu và xung đột

Tạo/sửa gọi API hiện có, không tạo kho dữ liệu trình duyệt thay backend. Sửa person/banner và PUT settings dùng ETag/If-Match của bản đã đọc.

Khi một người khác đã sửa, API trả 412; UI giữ bản nháp và yêu cầu tải bản mới rõ ràng. Không tự lấy ETag mới rồi ghi đè. Settings dùng luồng AdminActions hiện có cho MFA step-up khi cần.

Banner mặc định tắt. Ngày kết thúc phải sau ngày bắt đầu; bỏ ngày trong biểu mẫu gửi null để xóa lịch. Ngày giờ nhập theo múi giờ thiết bị và gửi ISO tới API.

Báo lỗi chỉ đọc/lọc; không thêm nút giải quyết hoặc đổi trạng thái khi API chưa có thao tác đó. UI không dựng lại nội dung chi tiết mà backend đã ẩn với AUDITOR.

## Lỗi phân trang được phát hiện và sửa

Trường hợp kiểm thử tạo 22 hồ sơ trong cùng một câu lệnh SQL, cộng một hồ sơ đã có, ban đầu chỉ tải được 21/23 hồ sơ. Nguyên nhân: timestamp PostgreSQL có microsecond, còn Date JavaScript chuyển về millisecond khi tạo cursor. Các bản ghi cùng timestamp ở cuối trang bị bỏ qua.

Query của các danh sách dùng paginated hiện đã cung cấp timestamp nguyên độ chính xác dưới tên nội bộ __cursor_time. Helper dùng giá trị này làm khóa cursor và loại bỏ trường nội bộ khỏi data JSON. Áp dụng cho danh sách admin phim/mùa/tập/user/people/banner/report/audit, catalog public/recommendation và thư viện dùng cursor thời gian.

Không đổi bảng, grant, route, DTO hoặc hợp đồng JSON công khai. Cursor vẫn ký HMAC và ràng buộc scope/filter. Các cursor cũ vẫn được chấp nhận; cần tải lại danh sách từ đầu để lấy cursor mới đủ độ chính xác.
